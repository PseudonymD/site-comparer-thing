# Decisions log

Reasonable calls made during the build, as asked for in the brief. Nothing here adds a backend or a paid service, and none of the 18 features was dropped.

## Data & pipeline

1. **Data is published gzip-compressed** (`features.bin.gz`, `cells.bin.gz`, `countries.bin.gz`). The raw layout is exactly as specified: uint8 cell-major `[cell][18]` and uint32 grid indices. GitHub Pages does not gzip binary files, so this saves ~40% of the download. The browser decompresses with `DecompressionStream`, and the loader also accepts uncompressed files. `python -m pipeline publish` copies only the `.gz` files and the JSON.
2. **Extra file `countries.bin`** (uint8 per land cell → index into `meta.countries`) handles offline reverse geocoding. It is built from Natural Earth admin-0 50m. Coastal cells whose centre falls in the sea take the nearest country.
3. **Land mask** = Natural Earth 10m land rasterised at 0.02° and averaged to 0.1°. Cells with ≥ 50% land count as land, which gives 2,143,220 cells. A 0.1° copy of the land fraction and country index is committed in `pipeline/assets/` (≈250 kB), so the pipeline and synthetic generator work offline. Ice stays a feature, not a mask.
4. **Terrain is computed in 10°×10° grid blocks** from Terrarium tiles at zoom 7 (≈1.2 km pixels at the equator). Each block mosaics only its tiles plus a 1-pixel margin, so cells never straddle chunks and p90 / max−min are exact per cell. Tiles with no land are never downloaded. TRI uses the Wilson et al. (2007) mean-absolute-difference form. Sea pixels (< −10 m) are ignored in cells that also contain land. Web Mercator ends at ±85.05°, so cells beyond that (inner Antarctic plateau) copy the nearest valid row.
5. **dask/rioxarray/xarray were not needed**: block processing with numpy keeps memory under ~3 GB, so they are not in `requirements.txt` (fewer install problems on Windows). `scipy` (resampling, nearest fill) and `h5py` (Black Marble / MERRA-2 HDF5) were added. Both are wheel-only. `pyhdf` is optional and reads MODIS HDF4. The rasterio wheels have no HDF4 driver, and pyhdf has no wheel for Intel Macs, so MODIS falls back automatically there.
6. **NASA POWER** is fetched through the *regional* climatology endpoint in 10°×10° boxes, one parameter per request, only for boxes with land, and cached as JSON. Temperatures are downscaled to the 0.1° DEM with a 6.5 K/km lapse rate when POWER reports grid-point elevations. "Annual min temperature" = coldest monthly mean of T2M_MIN. Precipitation is converted from mm/day to mm/yr.
7. **GIBS fallbacks** decode imagery back to values by inverting the layer's published colormap (nearest colour). Black Marble has no colormap, so the night-lights fallback is image luminance. It is flagged `proxy: true` and shown with a PROXY badge.
8. **MODIS NDVI** uses four seasonal months (Jan/Apr/Jul/Oct 2023) to cover both hemispheres' growing seasons with ~0.7 GB of downloads instead of 2 GB. MODIS LST uses all 12 months (needed for the coldest month).
9. **Ice fallback chain**: MCD12C1 class 15 → GLiM `ig` → Natural Earth glaciated areas + Antarctic ice shelves. Natural Earth leaves out the Antarctic ice sheet itself, so land south of 60°S counts as ice except the McMurdo Dry Valleys box. The real ice-free oases are below 0.1° resolution.
10. **GLiM** is ~1 GB and its PANGAEA URL may change. The module also accepts a manually downloaded copy anywhere under `pipeline/cache/glim/` or `GLIM_PATH`.
11. **Synthetic layers**: a source that fails falls back down its chain. The last resort is a physically motivated synthetic layer driven by latitude, real elevation and smooth noise, flagged in `meta.json` and the UI. The frontend is never blocked.
12. **Quick mode** (`--quick`): 0.5° grid, terrain zoom 4, US South-West bbox. This bbox contains Death Valley, the MDRS, Meteor Crater and Black Point, so the validation step has known analogs to test. In bbox runs, percentiles are relative to the bbox (`normalisation_domain: bbox_land`), and `publish` refuses them unless `--allow-bbox` is passed.

## Targets

13. **Target values come from the literature with citations** in `targets.json` (`raw[*].refs` + `references`). No automated LOLA/MOLA DEM extraction is done: the global products are many GB and the useful polar tiles have unstable URLs. Terrain targets are stated at the ~1 km baseline of the Earth features.
14. **Elevation as an atmosphere proxy**: vacuum targets (Moon) map to Earth's highest terrain, Mars targets to 4500 m (Altiplano-class plateaus, classic low-pressure / high-UV analogs). Default weight is low (0.5).
15. **High-resolution slope histograms** for the 30 m drill-down are lognormal fits to the literature median and p90 slopes at 20–30 m baselines. They are labelled as such in the UI.
16. **Validation** takes a site's score as the best cell within ±2 cells (~±20 km) of its published coordinates. Published coordinates are approximate, and coastal sites often fall in an ocean cell. Random land cells get the same treatment, so the comparison stays fair.

## Web

17. **Score overlay**: the worker paints a Web-Mercator RGBA image (one column per grid column, mercator-spaced rows) and encodes it to PNG with `OffscreenCanvas`. A MapLibre `image` source displays it. A `canvas` source would skip the PNG step, but its texture upload rendered black under software WebGL during testing. The PNG round trip costs ~100–150 ms and stays within the 500 ms budget.
18. **Basemaps**: Esri World Imagery (default, satellite) and Esri Dark Gray Canvas (toggle), with Esri Boundaries and Places for labels, all free with attribution (CARTO was dropped when its tiles began requiring an API key). **Globe** projection is a toggle (MapLibre v5). Flat Mercator is the default because it reads better on a projector.
19. **Colour stretch**: colours span the chosen Earth percentile (default p50) to the maximum of the current score distribution. Without this, scores bunch up in 0.6–0.9 and the map looks flat.
20. **Novelty** is precomputed once per cell in the worker. The 16 known analogs are fixed, so slider changes cost nothing extra.
21. **Pinned versions** older than two weeks at build time: maplibre-gl 5.24.0, vite 6.4.5, TypeScript 5.9.3, vitest 3.2.7.

## Improvement pass (14 Nov)

22. **SoilGrids gap policy (data bug fix).** SoilGrids does not map Antarctica, ice sheets or large lakes: 31.6% of 0.1° land cells, mostly Antarctic, because polar cells are small. Plain nearest-neighbour filling had copied peat-rich sub-Antarctic and tundra soils onto the Antarctic ice sheet and the McMurdo Dry Valleys (median 139 g/kg soil organic carbon; the real Dry Valleys hold < 1 g/kg, Burkins et al. 2000). The new rule (`pipeline/sources/soilgrids.py::fill_gaps`): nearest-fill only within 3 cells of mapped soil; SOC = 0 in remaining gaps that are ice-covered or south of 60°S; sand = 0 in remaining ice-covered gaps; anything left (lakes, ice-free polar desert) keeps nearest fill. The note is stored per feature in `meta.json` and shown on the About page. Effect on validation: McMurdo jumps to rank 26 (Moon south pole) and 51 (Mars north polar) of 2.1 M cells. AUC *falls* for the polar targets (south pole 0.75 → 0.73, north polar 0.64 → 0.58) because random Antarctic ice-sheet cells, 28% of the random sample, also stop being penalised. We kept the fix: it is a correction, and the lower numbers are the honest ones.
23. **Arcadia surface ice 0.3 → 0.** Our `ice` feature is *surface* permanent ice/snow cover. Arcadia's excess ice is buried under a dry, ice-free regolith lag (Bramson et al. 2015), so the surface target is 0. The old value rewarded partly glaciated cells. Effect alone: +0.01 AUC.
24. **Arcadia analog list revised (after seeing results, so not blind).** Removed Askja and Holuhraun: they are volcanic analogs with no ground ice. Added University Valley (Dry Valleys), the standard analog for ice-cemented ground under a dry surface (Heldmann et al. 2013), as a new known analog. Decomposition on the fixed data: original list 0.36; minus the two volcanic sites 0.51; plus University Valley 0.63. So most of the gain comes from the list, not the model, and about half of that from adding a second Dry Valleys site. The report prints both AUCs. Devon Island and Svalbard still rank below the median (see 25).
25. **Not changed, documented instead:** (a) relative humidity penalises humid-but-cold polar air, which is why Svalbard and Devon Island rank poorly; switching to absolute humidity would mean replacing a feature, so we left it for discussion; (b) Arcadia's diurnal-range target (60 °C) clamps to Earth's hot-desert maximum, which conflicts with its cold target; (c) no weights were tuned.
26. **Lava-tube target, cause found.** The basalt layer, weighted 3.0 for this target, is still synthetic and reads 0.0 at every volcanic analog (Kīlauea, Kazumura, Askja, Holuhraun, Black Point, Lanzarote). That alone costs each one the maximum basalt penalty. The rest is climate: windward Hawai'i gets ~1800 mm/yr of rain. Real GLiM data should fix the first part. The second is by design (the Moon is dry), so we did not reweight.
27. **GLiM fetcher.** The PANGAEA file path is correct. On 14 Nov PANGAEA answered HTTP 500 "the download area of PANGAEA has some problems with its backing file archive", which is why the earlier run fell back to synthetic. The fetcher now detects that page, says so, and points to the manual-download route. **Macrostrat** (no login, CC-BY 4.0) was added as a second source: small-scale map polygons whose *major* lithology is mafic. It could not be tested from the cloud session (macrostrat.org is blocked there), so the teammate smoke-tests it first (pipeline/README.md, "Basalt hot-fix"). Microsoft Planetary Computer was checked as an option, but it has no global lithology collection that we know of, and its STAC API was also blocked from the session.
28. **`python -m pipeline patch --features …`** recomputes only the named features on top of the published data and rebuilds targets, analogs and validation. It needs no other cache, so the basalt hot-fix works on any machine. Patched columns are exact. A changed target value on an untouched feature is mapped through an approximate CDF (≤ ~1/255 error) and listed in `meta.approximate_target_entries` (currently only `mars_arcadia.ice`, which maps exactly because 0 is the minimum). `run --only` now also takes feature ids (`--only basalt`).
29. **Cell-count percentiles.** Percentiles and the random baseline count cells, not km², so polar regions are over-represented (Antarctica ≈ 28% of cells). We note this as a limitation rather than changing the normalisation mid-competition.
30. **Discoveries are picked by rule, not by hand** (`pipeline/discoveries.py`, rule also stored in `discoveries.json`): default weights and filters, novelty α = 0.3, worker-style site clustering, Earth top 1% for the target, ≥ 500 km from every known analog, ≤ 2 per target, ≥ 300 km apart, ≤ 10 in total. Only the *names* are hand-made, from a small bbox gazetteer (`pipeline/assets/places.json`). The rule sends 9 of 10 picks to the cold high deserts of Central Asia (Tibetan Plateau, Qaidam, Gobi, Lop Nur, Pamir), because they are cold, dry, barren and > 4000 km from every analog on our list. One of them, the western Qaidam Basin, has already been proposed as a Mars analog (Xiao et al. 2017). We say so on the card ("not on our list, found independently") rather than claim it as new. `publish` regenerates both files, so they always match the data.
31. **Southern Africa spotlight**: six local places scored at their best cell within ±5 cells (~±50 km), since regions are large and coordinates approximate. Percentiles are against all of Earth's land. All sentences on the panel are generated from `spotlight.json`, except two static notes: the basalt-placeholder warning (shown only while basalt is synthetic) and why Vredefort scores low (no impact layer; an eroded crater in a wetter, farmed area).
32. **Region limit** (`r=safrica`) restricts the heatmap and candidate list to a bbox but keeps the histogram global, so "top x% of Earth's land" stays true.
33. **Deep links** encode target, weights (only when changed), filters (only when they differ from the target defaults), novelty, region, map view, selected cell, projection and basemap in the URL hash (`web/src/links.ts`, round-trip tested).
34. **Planetary side-by-side** uses NASA Trek WMTS tiles (Moon: LRO WAC global mosaic; Mars: Viking MDIM 2.1 colour) as plain `<img>` tiles, which need no CORS, next to Esri imagery at a similar north–south ground scale. Trek is unreachable from the cloud session used to build this, so the tile URLs could not be checked there. If they fail, the panel says so and links to the Trek portal. The lunar south pole is shown in the equirectangular product, which is stretched east–west near the pole, and the caption says so.
35. **Validation badge** thresholds: AUC ≥ 0.85 "works well", 0.65–0.85 "works moderately", < 0.65 "weak". The badge links to the matching row on the method page.
36. **Map-first loading.** The map and the known-analog markers appear as soon as the JSON files arrive (~100 kB). The 30 MB grid then streams in behind a progress card that explains what is loading. MapLibre is a separate long-cached chunk. We did not lazy-load MapLibre itself: the map is needed on first paint anyway.
37. **Tour = subtitles.** The six tour captions are exactly the cues in `docs/demo.srt` and run for 29.5 s, so one clean screen recording of `#tour` stays within the 30 s limit with subtitles burned in.
38. **OG image** is currently a crop of the older README screenshot, because Esri tiles can't be fetched from the cloud session. `web/scripts/screenshot.mjs` regenerates both images from the live site.
39. **Not done, needs a decision:** a Meteomatics "current conditions" line would need an API key, which means a serverless function. Per the brief we did not add a backend. Ask first.
